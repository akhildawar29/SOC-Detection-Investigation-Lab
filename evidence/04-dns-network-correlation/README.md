# DNS and Network Correlation Investigation

## Objective

Investigate DNS and network activity using Microsoft Sysmon telemetry in Splunk Enterprise and correlate network-related events with process execution activity.

## Data Sources

- Microsoft Sysmon
- Sysmon Event ID 1 — Process Creation
- Sysmon Event ID 22 — DNS Query
- Splunk Enterprise
- Windows 11 endpoint

## Investigation

Sysmon DNS telemetry was analyzed in Splunk to identify DNS queries generated by processes on the Windows endpoint. Event ID 22 provided visibility into domain queries and the processes responsible for generating them.

DNS events were then correlated with process execution telemetry to provide additional context around network activity. This allowed process behaviour and DNS activity to be examined together rather than as isolated events.

## Key Findings

- Sysmon Event ID 22 successfully captured DNS query activity.
- DNS events could be associated with the processes responsible for generating the queries.
- Process and DNS telemetry provided complementary evidence during investigation.
- Correlation improved visibility into the sequence of endpoint and network activity.
- Splunk provided a central location for investigating multiple Sysmon event types.

## Investigation Value

DNS telemetry can provide important context when investigating suspicious process execution. A process event may show what executed, while DNS telemetry can reveal domains subsequently queried by that process.

Correlating these data sources enables an analyst to reconstruct activity more effectively and identify relationships that may not be apparent when reviewing individual events.

## Analyst Takeaway

Combining process creation and DNS telemetry demonstrates an important SOC investigation technique: event correlation. Rather than treating alerts and events independently, analysts can connect endpoint and network evidence to develop a clearer understanding of system activity.
